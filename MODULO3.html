Autenticação: bcrypt + JWT em cookie

Hash de senha com salt, token assinado, cookie HttpOnly e o padrão Post/Redirect/Get.

3.1 Hash de senha

import bcrypt

def _hash_senha(senha: str) -> str:
    return bcrypt.hashpw(senha.encode("utf-8"), bcrypt.gensalt()).decode("utf-8")

def _verificar_senha(senha: str, senha_hash: str) -> bool:
    return bcrypt.checkpw(senha.encode("utf-8"), senha_hash.encode("utf-8"))
  • gensalt() gera salt aleatório por senha → senhas iguais geram hashes diferentes.
  • O salt fica embutido no hash: $2b$12$<salt22><hash31>.
  • 12 é o cost factor: 212 = 4096 rounds. +1 dobra o custo do atacante — e o seu.
  • checkpw compara em tempo constante → resiste a timing attacks.
Detalhe

Bcrypt trunca em 72 bytes. Se aceitar senhas longas, aplique SHA-256 antes do hashpw.

3.2 Geração do JWT

def _criar_jwt(usuario_id: int) -> str:
    expira = datetime.utcnow() + timedelta(minutes=JWT_MINUTES)
    return jwt.encode({"sub": str(usuario_id), "exp": expira},
                      JWT_SECRET, algorithm=JWT_ALG)

Estrutura header.payload.signature em Base64URL. O payload é legível por qualquer um — nunca coloque senha ali. A assinatura HMAC-SHA256 garante apenas integridade.

sub é string por exigência da RFC 7519 — por isso dependencies.py faz int(sub).

3.3 Cookie HttpOnly

response.set_cookie(
    "access_token", token,
    httponly=True,     # JavaScript não acessa → mitiga XSS
    samesite="lax",    # mitiga CSRF, permite o redirect do OAuth Bling
    max_age=JWT_MINUTES * 60,
    secure=True,       # ← ADICIONE em produção (só HTTPS)
)
Por que cookie e não header?

O front é Jinja2 (navegação por links e forms), não SPA. O navegador envia o cookie automaticamente; com Authorization seria necessário JS em cada requisição.

Por que "lax" e não "strict"?

Com strict, o cookie não seria enviado no retorno de bling.com.br → /auth/bling/callback, e get_usuario_id devolveria None, quebrando o OAuth.

3.4 Leitura da sessão

# dependencies.py
def get_usuario_id(request: Request) -> int | None:
    token = request.cookies.get("access_token")
    if not token:
        return None
    try:
        payload = jwt.decode(token, JWT_SECRET, algorithms=[JWT_ALG])
        sub = payload.get("sub")
        return int(sub) if sub else None
    except (JWTError, ValueError):
        return None

jwt.decode valida assinatura e exp automaticamente. algorithms=[...] é obrigatório: sem isso um atacante poderia forjar alg: none.

Retornar None em vez de levantar HTTPException é decisão consciente: cada router decide se redireciona para /auth/login ou exibe aviso.

Variante Depends para endpoints de API

from fastapi import Depends, HTTPException, status

async def usuario_autenticado(request: Request) -> int:
    uid = get_usuario_id(request)
    if not uid:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "Sessão expirada")
    return uid

Mantenha a versão simples para o callback OAuth.

Cadastro

result = await db.execute(select(Usuario).where(Usuario.email == email))
if result.scalar_one_or_none():
    return templates.TemplateResponse(
        request=request, name="cadastro.html",
        context={"erro": "E-mail já cadastrado."}, status_code=409)

db.add(Usuario(email=email, senha_hash=_hash_senha(senha)))
await db.commit()
return RedirectResponse("/auth/login?cadastro=ok", status_code=303)

Login

usuario = result.scalar_one_or_none()

# Mensagem genérica evita user enumeration
if not usuario or not _verificar_senha(senha, usuario.senha_hash):
    return templates.TemplateResponse(
        request=request, name="login.html",
        context={"erro": "E-mail ou senha inválidos."}, status_code=401)

resp = RedirectResponse("/dashboard", status_code=303)
return _set_jwt_cookie(resp, _criar_jwt(usuario.id))

Logout: delete_cookie("access_token") + 303.

Por que 303 e não 302?

Após um POST, o 303 See Other obriga o navegador a fazer GET no destino. Com 302 alguns clientes repetiriam o POST — é o padrão Post/Redirect/Get, que também impede reenvio ao apertar F5.

3.6 Integrando os schemas Pydantic

Seus routers usam Form(...) direto. Os schemas existem para validar antes de persistir:

from pydantic import ValidationError
from schemas.schemas import UsuarioCadastroInput

try:
    dados = UsuarioCadastroInput(email=email, senha=senha)
except ValidationError:
    return templates.TemplateResponse(
        request=request, name="cadastro.html",
        context={"erro": "E-mail inválido ou senha com menos de 6 caracteres."},
        status_code=422,
    )
db.add(Usuario(email=dados.email, senha_hash=_hash_senha(dados.senha)))
