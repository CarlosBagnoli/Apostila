OAuth2 com o Bling e ciclo de vida do token

Authorization Code, proteção anti-CSRF com state, Basic Auth na troca e refresh automático transparente.

4.1 Por que OAuth2 e não API key?

O usuário autoriza sua aplicação sem entregar a senha do Bling, com escopos limitados e possibilidade de revogação a qualquer momento.

4.2 O fluxo Authorization Code

1. GET /auth/bling/conectar → gera state, salva em cookie, redireciona para bling.com.br/oauth/authorize 2. Usuário autoriza no Bling 3. Bling → GET /auth/bling/callback?code=XYZ&state=ABC 4. Compara state (anti-CSRF) 5. POST /oauth/token (Basic Auth) com grant_type=authorization_code 6. Recebe access_token (1h) + refresh_token (30d) 7. token_service.save_token() → banco
@router.get("/bling/conectar")
async def bling_conectar(request: Request):
    state = secrets.token_hex(16)
    url = (
        "https://www.bling.com.br/Api/v3/oauth/authorize"
        f"?response_type=code"
        f"&client_id={BLING_ID}"
        f"&redirect_uri={BLING_REDIR}"
        f"&state={state}"
    )
    resp = RedirectResponse(url)
    resp.set_cookie("oauth_state", state, httponly=True, max_age=300)
    return resp

4.3 O parâmetro state

if request.cookies.get("oauth_state") != state:
    return RedirectResponse("/dashboard?erro=oauth_state_invalido")
Vetor de ataque

Sem o state, um atacante poderia induzir a vítima a vincular a conta Bling do atacante à conta dela na plataforma — passando a receber ou manipular dados fiscais. Use secrets (CSPRNG), nunca random.

O cookie expira em 300 s: tempo suficiente para autorizar, curto para replay.

4.4 Basic Auth na troca de token

def _basic_auth_header() -> str:
    credenciais = f"{BLING_CLIENT_ID}:{BLING_CLIENT_SECRET}"
    return f"Basic {base64.b64encode(credenciais.encode()).decode()}"

Base64 não é criptografia — é apenas transporte; a segurança vem do HTTPS. É exigência específica do endpoint /oauth/token; os demais usam Bearer.

4.5 Persistência com token único

await db.execute(
    update(BlingToken)
    .where(BlingToken.usuario_id == usuario_id, BlingToken.ativo == True)
    .values(ativo=False)
)
expires_at = datetime.utcnow() + timedelta(seconds=expires_in)
db.add(BlingToken(usuario_id=usuario_id, access_token=access_token,
                  refresh_token=refresh_token, expires_at=expires_at, ativo=True))
await db.commit()
Invariante

No máximo um token ativo por usuário. Sem a desativação prévia, scalar_one_or_none() em get_valid_access_token levantaria MultipleResultsFound no segundo conectar.

O Bling retorna expires_in (segundos); armazenamos o instante absoluto — mais fácil de comparar em qualquer requisição futura.

4.6 Refresh automático — o coração da integração

# Margem de 60s evita race condition entre validar e usar
if token.expires_at > datetime.utcnow() + timedelta(seconds=60):
    return token.access_token

try:
    data = await bling_client.refresh_access_token(token.refresh_token)
    token.access_token  = data["access_token"]
    token.refresh_token = data.get("refresh_token", token.refresh_token)
    token.expires_at    = datetime.utcnow() + timedelta(seconds=data["expires_in"])
    await db.commit()
    return token.access_token
except Exception:
    token.ativo = False      # refresh revogado → força reconexão manual
    await db.commit()
    return None
  1. Margem de 60 s — uma emissão em massa leva minutos; sem margem, o token poderia expirar no meio do lote.
  2. data.get("refresh_token", token.refresh_token) — se o Bling não devolver um novo, mantém o antigo. Sobrescrever com None quebraria a integração permanentemente.
  3. None como contrato — significa “reconecte no dashboard”. Todos os consumidores tratam isso.
# routers/pedidos.py — degradação graciosa
access_token = await token_service.get_valid_access_token(db, usuario_id)
if not access_token:
    return templates.TemplateResponse(
        request=request, name="pedidos.html",
        context={"pedidos": [],
                 "erro": "Integração com Bling inativa. Conecte na dashboard."})
Débito técnico #7

Você usa datetime.utcnow() (naive) mas o model tem DateTime(timezone=True) (aware). Comparar os dois levanta TypeError. Padronize:

from datetime import datetime, timezone
agora = datetime.now(timezone.utc)

Ou mantenha naive e remova timezone=True do model. O essencial é não misturar.

4.7 Ciclo completo do token

save_token ──► [ativo=true, expires_at=+1h] │ get_valid_access_token (cada operação) │ ┌───────────┴───────────┐ válido? expirado? │ │ retorna refresh_access_token │ ┌─────────┴─────────┐ sucesso falha │ │ atualiza+retorna ativo=false → None

Desconectar

@router.post("/bling/desconectar")
async def bling_desconectar(request: Request, db: AsyncSession = Depends(get_db)):
    usuario_id = get_usuario_id(request)
    if not usuario_id:
        return RedirectResponse("/auth/login")
    await token_service.deactivate_token(db, usuario_id)
    return RedirectResponse("/dashboard", status_code=303)

Note: POST, não GET — operação que altera estado.
